# ARMobile3D — Target UX Specification

Этот документ задаёт целевую UX-модель ARMobile3D для строительного контроля с использованием BIM-моделей и AR. Он является самостоятельным источником требований к информационной архитектуре, навигации, состояниям интерфейса, ключевым пользовательским сценариям и визуальному языку.

Документ должен позволять реализовать интерактивный web-прототип без знания внутренней архитектуры Unity-приложения. Конкретные размеры, окончательные тексты, иконки и микровзаимодействия можно уточнять при реализации, если они не меняют описанную здесь модель.

---

## 1. Цель продукта и UX-принципы

ARMobile3D — рабочий инструмент строительного контроля, где BIM служит пространственным контекстом. Интерфейс должен помогать сравнивать BIM с фактическим состоянием объекта, выбирать точный BIM-элемент, создавать и проверять замечания, позиционировать сцену, измерять расстояния, делать снимки и работать с несколькими моделями одновременно.

Основные принципы:

1. Пользователь работает с понятными задачами, а не с внутренними состояниями приложения.
2. Постоянные действия имеют стабильный смысл.
3. Многошаговая операция имеет явное название, текущий шаг/инструкцию, `Отмена` и `Готово` / `Далее`.
4. Выбор объекта сам по себе не двигает камеру и не открывает дочерний экран.
5. После дочернего действия пользователь возвращается в тот же рабочий контекст, если явно не сменил задачу.
6. Viewport остаётся главным визуальным объектом интерфейса.
7. Технические концепции рендера не должны становиться пользовательскими режимами.
8. Редкие действия допускают дополнительный шаг; частые должны быть доступны непосредственно.
9. Телефон и планшет используют одну IA, различаясь способом размещения surfaces.

## 2. Основная информационная архитектура

Открытый `Project` задаёт рабочий контекст. Внутри него существуют две основные рабочие области:

- **Сцена**
- **Замечания**

Viewport является общей пространственной поверхностью Project: в `Сцене` он является главным содержимым, а в `Замечаниях` используется для проверки конкретного замечания без выхода из review-задачи.

Уровни интерфейса:

| Уровень | Назначение |
|---|---|
| App level | Local models, Global Settings, Account / organization, выход |
| Project context | Название текущего Project и редкое действие смены Project |
| Primary workspace | `Сцена \| Замечания` |
| Viewport mode | `BIM \| AR` |
| Contextual layer | Действия выбранного BIM-элемента, модели или замечания |
| Workflow layer | Явная многошаговая задача с Cancel / Done |

Смена Project полностью закрывает текущую сцену и сбрасывает scene-scoped state. Автоматически восстанавливать состояние предыдущей сцены не нужно. Предупреждение требуется только при реально значимых несохранённых изменениях.

---

## 3. Project shell

Пока открыт Project, пользователь всегда должен понимать, какой Project открыт, находится он в `Сцене` или `Замечаниях`, и — если виден viewport — используется `BIM` или `AR`.

Базовая структура shell:

`[Current Project]   [Сцена | Замечания]   [App / Account]`

`BIM | AR` располагается рядом с viewport и не является глобальной навигацией приложения.

Название текущего Project постоянно видно. Tap/click по нему открывает небольшую project surface с информацией и вторичным действием `Сменить проект`. Смена Project — редкий сценарий, поэтому отдельная постоянная кнопка `Projects` не требуется.

App-level surface содержит `Local models`, `Settings`, `Account / organization` и выход. Эта область не должна конкурировать с рабочими действиями Project.

---

## 4. Рабочая область «Сцена»

`Сцена` предназначена для просмотра, сравнения, подготовки и пространственной работы.

Основные стабильные entry points:

| Entry point | Назначение |
|---|---|
| **Модели** | Состав текущей сцены, добавление, видимость, структура, фокус, удаление, редкая коррекция отдельной модели |
| **Позиционирование** | Позиционирование всей сцены и работа с маркерами |
| **Измерить** | Пространственная линейка |
| **Снимок** | Capture viewport и последующая 2D-разметка |

Отдельной универсальной палитры Tools быть не должно. Minimap, этажи и другие spatial utilities появляются контекстно.

---

## 5. BIM и AR

Пользователь видит два режима представления одной и той же сцены.

### BIM

- чистая цифровая сцена;
- tap по геометрии выбирает точный BIM-элемент;
- доступен режим камеры `Орбита / Осмотр`;
- доступны общие Scene tools.

### AR

- та же сцена поверх камеры устройства;
- постоянный reticle показывает текущий target;
- отдельное действие `Выбрать` фиксирует точный BIM-элемент;
- доступны AR camera/view controls;
- общие Scene tools доступны в рабочей области `Сцена`.

Отдельного пользовательского режима `MR` нет. Depth/occlusion входят в настройки AR. Отдельного инструмента `Aim` нет: reticle является штатным способом выбора в AR.

### AR view controls

**Прозрачность BIM** регулирует прозрачность всей BIM-сцены. Она не зависит от выбранной модели или BIM-элемента, сохраняется при `BIM ↔ AR` и при временных workflows, но сбрасывается при смене Project.

**Учитывать окружение** включает depth/occlusion реального окружения, чтобы BIM корректно перекрывался реальными объектами.

**Показывать скрытое** показывает заливку/очертание BIM-геометрии за реальными препятствиями и помогает понимать продолжение труб, трасс и других элементов за стеной или перекрытием.

**Фонарик** — utility камеры AR. Он не принадлежит Remarks и автоматически выключается при выходе из AR/camera context или смене Project. Его включённое состояние не восстанавливается при следующем входе в AR.

---

## 6. Выбор BIM-элемента

Во всех сценариях существует одна сущность: **Selected BIM element**.

Источники выбора:

- tap по геометрии в BIM;
- reticle + подтверждение в AR;
- выбор элемента из Structure.

Результат одинаков независимо от источника.

Selection не двигает камеру автоматически, не открывает Attributes/Remark автоматически и сохраняется при открытии/закрытии дочерних surfaces, если пользователь не выбрал другой элемент. `Фокус` — отдельное явное действие.

Минимальные contextual actions выбранного элемента:

- `Атрибуты`;
- `Создать замечание`;
- `Прозрачность элемента`;
- `Скрыть`;
- `Фокус`, где пространственное перемещение действительно требуется.

`Скрыть` исключает элемент из hit testing, чтобы можно было выбирать геометрию глубже. Должно существовать recovery-действие `Показать всё`.

Прозрачность отдельного элемента и прозрачность всей сцены в AR — разные controls.

## 7. Models panel

`Модели` открываются как panel/sheet поверх viewport, а не как самостоятельный рабочий экран. Panel отвечает только на вопрос: **что сейчас загружено в сцену?**

Строка модели содержит имя и состояние видимости. Источник модели после загрузки не показывается. Tap/click по строке раскрывает действия модели, но не меняет Selected BIM element.

Действия модели:

- `Фокус`;
- `Структура`;
- `Корректировать положение`;
- `Удалить из сцены`.

Основное позиционирование перемещает всю сцену, сохраняя взаимное положение моделей. Коррекция одной модели — редкий и явно обозначенный scope.

### Structure

`Структура` открывается поверх того же viewport и содержит поиск, BIM-дерево и управление видимостью. Выбор элемента в дереве создаёт тот же Selected BIM element, что и выбор геометрии. Камера не перемещается автоматически — для этого есть `Фокус`.

---

## 8. Add Models

`+ Добавить` из Models открывает selector моделей **текущего Project**. Project уже задан контекстом и повторно не выбирается.

Серверные модели организованы в глубокой иерархии Locations, модели являются листьями дерева.

Требования:

- полноценное раскрываемое дерево;
- пользователь выбирает только конкретные модели, а не Location целиком;
- выбор сохраняется при переходе между ветками;
- можно выбрать модели из разных Locations;
- выбранные модели добавляются в одну сцену одним действием;
- уже загруженные модели имеют состояние `Загружено` и повторно не выбираются;
- поиск работает по всему дереву;
- результат поиска показывает Location path, чтобы различать одинаковые имена.

Пример:

`Корпус 1 / Секция 3 / Этаж 7 / ОВ → Ventilation_07`

`Из локальных моделей…` — отдельное вторичное действие и не выглядит как искусственная ветка серверного дерева.

---

## 9. Local models

`Local models` — app-level библиотека, доступная двумя способами.

Из `Сцена → Модели → Добавить → Из локальных моделей` она работает как picker; основное действие — добавить выбранную локальную модель в текущую сцену.

Из `App → Local models` она работает как самостоятельная библиотека с просмотром, импортом, удалением, экспортом и организацией файлов.

Импорт локального файла не должен автоматически загружать его в текущую сцену.

---

## 10. Позиционирование и маркеры

`Позиционирование` — одна пользовательская задача. Внутренние способы могут сохраняться внутри неё: HandTap, Two Points, Adjustment, Scan Marker. Они не должны выглядеть как независимые глобальные режимы.

Основной scope — вся текущая сцена.

Коррекция одной модели доступна из Models и имеет явно обозначенный scope. Допустимы Move, Rotate и Scale. Scale не является обычным действием позиционирования всей сцены.

Любой многошаговый способ позиционирования показывает название задачи, текущий шаг/инструкцию, `Отмена` и `Готово` / `Далее`. `Отмена` возвращает состояние до начала незавершённого изменения.

Marker — объект позиционирования. Виртуальный marker связан с BIM; физический QR/Aruco является внешним ориентиром. Физический marker может идентифицировать модель при первоначальном выравнивании или корректировать уже загруженную сцену.

Tap по существующему marker только выбирает его и открывает contextual actions; сцена автоматически не двигается.

---

## 11. Измерение и Capture

`Измерить` запускает transient spatial ruler. Ruler не является отдельной Project-сущностью, остаётся 3D-объектом и должен быть виден на screenshot, если активен в момент Capture.

Отдельная пользовательская концепция Note не требуется.

Capture запускается из viewport без разрушения текущего контекста. После снимка открывается 2D editor. BIM, ruler и другие 3D-элементы уже запечены в изображение; 2D markup добавляется после Capture.

Вне Remark результат можно сохранить или поделиться им. Внутри Remark результат становится attachment текущего замечания.

---

## 12. Замечания

`Замечания` — отдельная Project-level рабочая область, тесно связанная с viewport.

Поддерживаются два равноправных сценария:

1. **viewport-first** — новое замечание создаётся из выбранного BIM-элемента;
2. **remark-first** — пользователь проверяет существующие замечания во время физического обхода.

### Создание замечания

Основной flow:

1. Выбрать точный BIM-элемент.
2. `Создать замечание`.
3. Указать точку на выбранном элементе.
4. Просмотреть автоматически собранные материалы.
5. При необходимости точечно добавить фото, AR/BIM screenshot или другой материал.
6. Заполнить `Название` — обязательное поле.
7. При необходимости заполнить `Описание`.
8. Создать remark.
9. Вернуться в исходный viewport context.

Точка замечания привязывается к выбранному BIM-элементу. Материалы доступны для просмотра и удаления; редактирование конкретного attachment может быть добавлено без перестройки flow.

### Detail

Строка списка открывает `Remark Detail` без автоматического движения камеры и без перехода в viewport.

В Detail доступны название, описание, материалы, статус, редактирование и `Показать в модели`.

Статус изменяется прямо в Detail. Некоторые переходы могут требовать короткий комментарий через небольшой inline/modal input.

---

## 13. Review viewport

`Показать в модели` из Remark Detail открывает специализированный viewport **внутри задачи проверки замечания**. Это не переход в обычную `Сцену`.

Доступны:

- навигация камеры;
- `Фокус` на замечании;
- `BIM | AR`;
- AR view controls;
- Capture / добавление материала;
- действия текущего Remark;
- Detail в подходящей responsive surface.

Недоступны Models, Positioning и Ruler.

Если пользователь явно переключается из review viewport в `Сцену`, review context закрывается, текущий ракурс камеры сохраняется, а viewport становится обычным Scene viewport.

`Предыдущее / Следующее замечание` не используются: порядок проверки определяется физическим перемещением пользователя по объекту.

На телефоне после `Remarks list → Detail → Show in model → Back` восстанавливаются filters, рабочая выборка, scroll position и выбранное замечание, если уместно. На планшете предпочтительно сохранять список рядом с viewport.

---

## 14. Minimap и этажи

Minimap относится к конкретной MefModel и является spatial navigation surface, а не картой всего Project или всей сцены.

Storey существует только внутри map и влияет только на её отображение.

Remarks могут отображаться contextual layer карты во время review.

Источник карты должен быть явным и стабильным: map не должна молча переключаться на другую модель вслед за selection.

Постоянная кнопка `Update Map` не нужна. Предпочтительна автоматическая регенерация либо явное stale-state с предложением обновить карту.

---

## 15. Responsive model

Одна IA используется на планшете и телефоне.

### Планшет

Viewport остаётся основным фоном. Models, Structure и Remark Detail предпочтительно показывать как боковые panels/surfaces. Review — список + viewport. Add Models — широкая side/overlay surface.

### Телефон

Сложные surfaces могут занимать почти весь или весь экран, если после закрытия полностью восстанавливаются viewport, camera, selection, filters, scroll position и допустимый незавершённый context.

Structure, Add Models и Remark Detail могут быть полноэкранными. Show in model временно заменяет список viewport-ом и корректно возвращается назад.

---

## 16. Правила сохранения контекста

| Переход | Поведение |
|---|---|
| `BIM ↔ AR` | Сохраняются сцена, selection и AR view settings |
| Выход из AR | Фонарик выключается |
| `Сцена → Замечания` | Сцена продолжает существовать |
| `Замечания → Сцена` | Возврат к существующей сцене |
| `Remark → Показать в модели` | Остаёмся в review context |
| `Review viewport → Сцена` | Review закрывается, текущий ракурс сохраняется |
| Child surface → Back | Восстанавливаются camera/selection/list context |
| Смена Project | Сцена и scene-scoped state сбрасываются |

---

## 17. Концепции, которых не должно быть в целевом UX

- Easy Mode;
- отдельный MR mode;
- Aim как отдельный tool;
- Projection как техническое название;
- универсальная Tools palette;
- Note как отдельный spatial tool;
- Save Scene;
- ручное сохранение marker-данных обратно в модель;
- Layers как самостоятельная пользовательская модель вместо Structure;
- Pointing как отдельный tool;
- Settings как router для model/workspace state;
- пользовательское управление серверным cache.

## 18. Contract для интерактивного web-прототипа

Web-прототип моделирует пользовательские состояния и переходы, а не 3D-движок. Настоящий BIM renderer не требуется: допустимы статические или условные viewport backgrounds с интерактивными hotspot-объектами.

Минимальная state model:

```text
app
  currentProject
  workspace: scene | remarks

scene
  viewportMode: bim | ar
  cameraContext
  selectedBimElement
  loadedModels[]
  hiddenElements[]
  ar:
    sceneOpacity
    environmentOcclusion
    showHiddenGeometry
    flashlight
  activeSurface:
    none | models | addModels | structure | remarkDetail | localModels
  activeWorkflow:
    none | positioning | ruler | capture | markerEdit | remarkCreate

remarks
  filters
  scrollPosition
  selectedRemark
  reviewViewport: on | off
```

Прототип должен симулировать BIM/AR switch, selection элемента, contextual actions, Models, hide/show, Add Models tree, выбор моделей из разных Locations, Positioning workflow, Ruler, Capture editor, создание Remark, Remarks list, Detail, status change, Show in model, сохранение list context, AR opacity/settings, transient flashlight и смену Project с reset scene state.

### Representative screens

1. Tablet — Scene / BIM, neutral viewport.
2. Tablet — Scene / AR.
3. Tablet — selected BIM element.
4. Tablet — Models panel.
5. Tablet — Add Models tree.
6. Tablet — Positioning workflow.
7. Tablet — Remarks list + Detail / viewport.
8. Tablet — Remark review viewport.
9. Phone — Scene / AR.
10. Phone — Remarks list → Detail → Show in model → Back.
11. Phone — Add Models fullscreen tree.
12. App-level — Local models library.

### Минимальные fixtures

- 1 текущий Project;
- 3–5 уровней Location hierarchy;
- 8–15 моделей в разных ветках;
- 3 загруженные модели;
- 5–8 BIM-элементов для selection;
- 6–10 Remarks с разными статусами;
- 2–3 attachments на нескольких Remarks;
- одна MefModel с minimap;
- несколько marker points.

Использовать реалистичные строительные названия, а не абстрактные `Item 1` / `Model A`, если это не мешает скорости реализации.

### Критические переходы

```text
Scene → Models → Add Models → выбрать несколько моделей → Add → Scene
```

```text
Scene → выбрать BIM element → Create Remark → point → materials → title → Create → Scene
```

```text
Remarks → Remark Detail → Show in model → AR → сменить status → Back → тот же Remarks list context
```

```text
Remarks → Show in model → Scene → продолжить работу в том же camera position
```

```text
Scene / AR → opacity 40% → BIM → AR → opacity остаётся 40%
```

```text
Scene / AR → flashlight ON → BIM → AR → flashlight OFF
```

```text
Project A → Scene state → сменить Project → новая пустая scene state
```

## 19. Visual Style Reference

Визуальная оболочка должна сохранять характер текущего ARMobile3D: светлые floating glass / frosted-like surfaces поверх BIM/AR viewport, большие скругления, primary-blue active state, тёмные outline icons и крупные touch-friendly controls. Viewport остаётся главным визуальным объектом; UI размещается поверх него компактными группами controls и rounded sheets, а не превращает приложение в тяжёлую dashboard-компоновку.

Основные tokens и patterns:

- `PRIMARY`: `#00A2E1` — active/selected, primary CTA;
- `DARK`: `#172B4D` — основной text/icon;
- `WHITE`: `#FFFFFF` — text/icon на primary;
- `QUATERNARY`: `#7B8395` — secondary content;
- `SURFACE_LIGHT`: `#F1F2F6` — light/glass surfaces;
- основной шрифт — **Roboto**;
- базовый rounding — `16px`;
- небольшие internal controls — `12–16px` radius;
- standalone controls — около `28px`;
- крупные cards/sheets — примерно `52–76px`;
- pills/round controls — full pill/circle;
- базовый shadow — `0 4px 4px rgba(0,0,0,0.25)`;
- крупные floating surfaces могут использовать `0 16px 80px rgba(0,0,0,0.12)`;
- характерный border — около `2px solid rgba(0,0,0,0.10)`.

Подтверждённая крупная typography scale:

| Style | Font | Size / Line-height |
|---|---|---|
| H4 | Roboto Light 300 | 24 / 30 |
| H4 Medium | Roboto Medium 500 | 24 / 30 |
| H3 | Roboto Light 300 | 30 / 38 |
| H3 Medium | Roboto Medium 500 | 30 / 38 |
| H3 Semibold | Roboto SemiBold 600 | 30 / 38 |
| H2 | Roboto Regular 400 | 34 / 40 |
| H2 Medium | Roboto Medium 500 | 34 / 40 |
| H2 Semibold | Roboto SemiBold 600 | 34 / 40 |

Для web-прототипа можно добавить меньшие body/label styles, сохраняя Roboto и ту же иерархию весов.

### Surface и controls

Характерная surface: `#F1F2F6`, большой radius, тонкий border, мягкая тень. Сильный backdrop blur не обязателен: glass-эффект может создаваться surface + border + shadow.

`BIM | AR` — light glass segmented pill. Active item — `#00A2E1` + white text; inactive — light/transparent + `#172B4D`.

Round icon buttons: светлая круглая surface, outline icon, dark neutral state, white icon на primary state, крупная touch area. Не превращать весь интерфейс в набор неразличимых icon-only controls: неоднозначные действия должны иметь label или очевидный contextual placement.

Primary CTA: `#00A2E1`, white text, pill shape, Roboto Medium. Применение: `Создать`, `Добавить N моделей`, `Готово`.

Secondary action: light glass surface, dark text, большой radius, визуально слабее primary CTA.

### Panels, viewport и minimap

Models, Structure, Add Models, Remark Detail и workflow panels используют большие rounded light surfaces поверх viewport. На планшете viewport желательно оставлять видимым; на телефоне сложная surface может занять весь экран.

BIM viewport: тёмный/нейтральный фон, модель доминирует, mode switch и utilities плавают по краям. AR viewport: camera feed занимает фон, BIM overlay находится поверх, reticle является частью camera interaction, AR controls не перекрывают центральную рабочую область.

Minimap — rounded light/glass surface с тёмной схемой карты, primary-blue акцентами, markers, orientation/cursor и floor control внутри карты.

Иконография преимущественно outline. Active state лучше выражать цветом/surface, а не полной сменой icon style.

Обязательно сохранить: `#00A2E1`, `#172B4D`, Roboto, light/glass floating surfaces, большие радиусы, round utility buttons, segmented `BIM | AR`, rounded sheets, blue pill CTA, rounded media thumbnails, тонкие borders, мягкие shadows, outline iconography и доминирующий viewport.

Не требуется переносить старое расположение controls, старую bottom-tab IA, техническое деление Tools/Settings, абсолютные размеры старых макетов, сильную blue tint камеры, platform-specific decorative patterns или конкретный набор glyphs.

## 21. Definition of Done первой web-версии

Первая web-версия достаточна для UX-проверки, если:

1. реализованы tablet и phone responsive layouts;
2. работают ключевые переходы, описанные выше;
3. state меняется предсказуемо;
4. viewport визуально остаётся главным содержимым;
5. Scene и Remarks ощущаются как две задачи одного Project;
6. BIM и AR ощущаются как два способа просмотра одной сцены;
7. review viewport не превращается в обычную Scene без явного действия пользователя;
8. Add Models отражает глубокую Location hierarchy;
9. state сохраняется и сбрасывается по правилам документа;
10. визуальный язык соответствует разделу Visual Style Reference.
